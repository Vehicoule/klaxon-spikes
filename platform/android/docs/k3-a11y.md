# K3-suite — pont TalkBack canonique Android (kx_a11y_sync_*)

Mission : brancher le squelette provider K2-prep sur l'ABI partagée figée
(même contrat que le shim macOS). Plateforme : émulateur kx36 API36 x86_64,
Ganesh-GLES (rendu logiciel SwiftShader — aucune extrapolation device).

## Architecture livrée

```
zig  k.host.syncA11y(h, root, alloc, selected_nodes)   [host.zig, gated is_android]
      └─ collectSemantics → kx_a11y_sync_begin(win,1.0)
         → N× kx_a11y_sync_item(win, node*, parent_node*, role, label0, hint0, x,y,w,h, flags)
         → kx_a11y_sync_end(win) → 1 si muté
C++ main.cpp (glue JNI, thread SDL)
      ├─ map ident(ptr Node*) ↔ nodeId(int, ≥1, stable) ; 0 = racine
      └─ → KxA11yProvider.onSyncBegin/Item/End (statiques Java)
Java KxA11yProvider extends AccessibilityNodeProvider [KxSurface, importantForAccessibility=YES]
      ├─ store synchronized cur/next ; strings COPIÉES à onSyncItem
      ├─ createAccessibilityNodeInfo : className(role), flags→enabled/focusable/
      │   focused/selected, checkable+checked (role 2|3), bounds écran
      │   (getLocationOnScreen), setParent/addChild
      ├─ onSyncEnd muté → TYPE_WINDOW_CONTENT_CHANGED ; delta focus →
      │   TYPE_VIEW_FOCUSED (+TYPE_VIEW_SELECTED si role==6 listitem)
      └─ performAction ACTION_CLICK → nativePerformAction → cb zig
zig  onA11yAction(ident,0) → slot pending (marshalling UI→SDL) →
     tick() draine → pointer_down+up au centre des bounds (ui.hit)
```

Rôles zig→contrat : none/text/image/divider→0 generic, button→1,
toggle→2 checkbox, slider→3, text_field→4, list→5, list_item→6, header→7.
Flags : disabled 1 | focusable 2 | focused 4 | selected/checked 8.
`selected` = liste de nœuds « état on » passée par l'app (toggle.on,
slider>0, selected_slot) — SemItem ne porte pas l'état, c'est métier.

## Vérifs exécutées (émulateur, TalkBack réel)

1. **TalkBack réel interroge le provider** : >1400 appels logcat
   (createAccessibilityNodeInfo, performAction ACCESSIBILITY_FOCUS id=3,
   events TYPE_VIEW_FOCUSED) — capture k3-a11y-logcat.txt.
2. **uiautomator dump hiérarchie finale** : 93 nœuds — header, Button
   "Ajouter 100 pistes", CheckBox, SeekBar, EditText, ListView "Bibliothèque",
   items listés avec bounds/classes exactes (k3-a11y-dump.xml).
3. **ACTION_CLICK e2e** : `am start --ei kx_a11y_action 10` →
   performAction(10,16) → nativePerformAction → cb zig → tap →
   **Piste #0 selected=true (uiautomator) + surbrillance violette**
   (139,126,233) + onSyncEnd mutated=1.
   *Honnêteté* : gestes TalkBack non injectables via `input` → l'appelant
   ACTION_CLICK est un pont debug (intent), le chemin provider→zig est réel.
   TalkBack réel prouvé séparément (appels provider continus).
4. **Flags propagés** : selected=true sur Piste #0 (click), CheckBox
   (toggle.on), SeekBar (slider>0).

## Pièges consignés

- `am start -e` passe des **String extras** → `getIntExtra` = -1. **`--ei`**.
- Activity `singleInstance` : `am start` → `onNewIntent`, et `getIntent()`
  garde l'ancien intent **sans `setIntent()`** — extra jamais lu sinon.
- `#include <unordered_map>` dans `extern "C"` → erreur « templates must
  have C++ linkage » — include en tête.
- Fonctions file-scope zig → `k.host.syncA11y(&h, ...)`, pas `h.syncA11y`.
- `TYPE_VIEW_CLEAR_ACCESSIBILITY_FOCUS` n'existe pas →
  `TYPE_VIEW_ACCESSIBILITY_FOCUS_CLEARED`.
- Logcat saturé par le spam TalkBack → filtrer le tag `KX-A11Y`.
- id maps C++ jamais élaguées (spike) — croissance bornée par vivants en prod.
- ACTION_FOCUS (action=1) passé au cb zig en ext locale (non contrat, bonus).
